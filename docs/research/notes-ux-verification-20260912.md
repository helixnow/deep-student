# 笔记模块 UX 修复验收（2026-09-12）

## 范围

本轮针对 Crepe 笔记模块的三种使用形态进行真实桌面应用验证：学习桌面窗口、资源管理器侧栏、393px/375px 窄窗口移动布局。验证使用 `npm run tauri dev` 启动的真实 Tauri 应用与本地 UI bridge，未使用 demo 页面。

## 已完成并实测

- 桌面工具栏采用可收缩布局，窄内容区自动隐藏次要内联按钮；按钮通过 `aria-pressed`/`aria-checked` 反映当前粗体、标题、列表等格式状态。
- 属性与链接在窄窗口切换为完整子页，在宽窗口与正文并排，不再以绝对定位覆盖正文。
- 资源管理器、正文、分屏编辑器的 pane 具备明确的 `min-width/min-height` 与隔离层；打开资源管理器后实测侧栏约 272px，正文仍可编辑。
- 移动端 5 个低频动作收进“更多笔记操作”菜单，菜单项达到 44px 触控高度；标题区与正文间距收紧，正文首屏提前显示。
- 链接命令改为先弹输入框，确认合法 URL 后插入并恢复编辑器焦点；Slash 菜单输入 `/` 后用方向键和 Enter 转换二级标题，真实成功。
- 图片命令在打开文件选择器前保存选区，返回后仅在同一可编辑实例中恢复选区并插入，取消选择不会插入空节点。
- 修复编辑器 250ms 合并保存与窗口/响应式卸载之间的竞态。桌面立即切到移动、移动立即切回桌面两条路径均验证内容保留。
- 关闭分屏标签后主标签保持可编辑；分屏标签关闭按钮可命中，两个 pane 的格式栏均无重叠。

## 仍需设备或环境支持的验证

- 本轮没有真实 iOS/Android 触屏键盘与中文 IME；393px/375px 是 Tauri 窄窗口验证，不能替代真机惯性滚动、软键盘顶起和选择手势。
- Notion 未登录 workspace，无法对其完成同一组端到端操作；对照依据为公开交互规范与既有审计记录。Obsidian 已在隔离 vault 验证基础编辑与文件树，但未把其插件生态行为作为本模块要求。
- 原生文件选择器、阅读模式、查找替换、表格/折叠块、撤销重做和 wikilink 的完整往返仍应在发布前各跑一遍；当前代码路径已保留，尚未将这些结果写成通过结论。
- 选区浮条与 Crepe 默认工具栏目前仍是两套能力，尚未发现同屏重叠的可复现证据，因此没有删除引用到聊天能力；后续应在真实鼠标选区和窄窗口各验证一次。

## 根因判断

体验差距主要来自交互状态分散：编辑器、窗口 pane、资源树和移动抽屉各自维护可见性与焦点，响应式切换会触发卸载；保存又依赖延迟合并回调，导致用户感知为“偶尔失效”。本轮优先收敛布局边界、焦点归属和保存生命周期，保留 Crepe 以避免迁移造成新的内容模型风险。

## 底座调研结论

短期不建议替换 Crepe。迁移到 BlockNote/Tiptap 会带来 Markdown、附件、思维导图、AI 产物和现有 DSTU 保存协议的重写成本；Lexical/ProseMirror 原生方案同样需要重建当前插件。Crepe 基于 Milkdown/ProseMirror，已有 slash、callout、toggle、表格和 Markdown 往返能力，当前瓶颈是宿主 chrome、焦点和状态管理，而不是文档模型本身。

中长期可建立编辑器适配层，先把 `getMarkdown/setMarkdown/selection/commands` 从 Notes 组件抽出，再以 BlockNote 或 Tiptap 做实验性实现。只有在完成同一套真实操作矩阵并证明 Crepe 在输入法、协同或大文档性能上存在不可修复差距时，才值得切换底座。

## 结论

本轮修复已改善桌面、资源管理器和移动端的可见布局、格式反馈、命令焦点与保存可靠性；不能据此宣称已经达到 Notion 或 Obsidian 的完整交互水平。发布前应完成上面的剩余操作矩阵，并在至少一台真实触屏设备上复验。
