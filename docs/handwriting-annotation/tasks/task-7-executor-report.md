# Task 7 executor — implementation status

## Implemented in `src-tauri/src/chat_v2/tools/ink_executor.rs`

- Fixed the duplicate `InkRenderMapping` import: canonical domain type is from `crate::vfs::ink`; `InkVisualArtifactRef` is from `dstu_core::agent`.
- Registered executor supports the six exact names (bare or one `builtin-` prefix). Existing create/get branches remain. `ink_create` and executor write operations scope client IDs to trusted session + tool family + client ID, not run ID.
- `ink_render` strictly parses its public schema, converts normalized crop to the frozen logical-page rectangle, flushes through `crate::ink_bridge::render_ink_snapshot`, and persists a trusted typed ref to the Chat block via `persist_render_artifact_ref`. Its output is bounded snake_case `pages[]` metadata including file/resource/artifact/render IDs, page crop and dimensions; no image bytes or URL are returned.
- `ink_prepare` and `ink_export` call the landed `crate::ink_jobs::prepare_source_ink` and `export_ink_document` APIs with the trusted session/call identity and cancellation token. Export output includes file/resource locator metadata and per-page entries; neither branch substitutes fake success.
- `ink_apply_ops` uses the actual `crate::ink_bridge::flush_ink_editor` when a window exists; windowless execution still requires migrated Chat DB for durable receipt persistence. It rejects missing Chat DB in every build. Operations are strictly decoded from serialized JSON bytes with deny-unknown helper structs, allowlists and 1–100 bounds; caller IDs/author/timestamps are rejected; backend page/object IDs are stable per session-scoped operation ID and operation index.
- Apply loads immutable render artifacts through `VfsInkArtifactRepo::load_for_document_with_conn`, enforces document/revision/page provenance, normalizes missing crop to full page, computes a pure canonical preview and VFS input hash, stores the typed bounded PREPARED receipt in `chat_v2_blocks.ink_undo_json` before VFS mutation, invokes `VfsInkOperationRepo::apply_with_conn`, verifies the canonical receipt and promotes the Chat receipt to COMMITTED. Existing same-session receipts preserve original timestamps and changes for retries; conflicting/unprovable states fail closed. Post-commit Chat receipt persistence failure is reported as committed with `undo_available: false` and `receipt_status: unavailable`. Success output omits geometry and object payloads and emits `ink:changed` for a window-backed call.
- `InkUndoReceipt` schema currently persists schema_version/session/message/block/call/document/operation/public input hash/created_at/previous and result revisions/canonical VFS input hash/object changes/appended page IDs/committed. The VFS input hash is a non-optional SHA-256 string to match the canonical VFS receipt. A migrated-Chat test exercises PREPARED → COMMITTED column roundtrip; apply success test asserts a committed receipt with object changes.
- A real migrated VFS + Chat DB producer test creates a frozen PNG artifact and asserts its trusted ref is persisted under the tool block and survives generic `ctx.save_tool_block`. Dynamic High sensitivity remains on update/remove; no approval bypass was added.
- Shared undo wire DTOs/helpers (`InkUndoReceipt`, `InkUndoObjectChange`, `object_changes`) are `pub(crate)` for the separate undo-command owner to reuse without defining a duplicate schema.

## Regression coverage and verification state

- Receipt trust boundary: lookup joins the real block/message rows and verifies session, message, block, tool name, persisted call ID when present, public tool input hash, document, schema version, size bounds and required hashes. Malformed JSON/schema fails closed. PREPARED/COMMITTED writes are transactionally bound to the actual message/session and existing block tool/call/input; committed or mismatched receipts cannot be overwritten. Tests cover parent/tool mismatch, malformed receipt, and round-trip with a valid canonical input hash.
- Terminal persistence: a SQLite trigger test aborts terminal `chat_v2_blocks` update after a real apply commit. Executor now converts a would-be success to a failure result while preserving `status: committed` and `committed: true`; the test checks VFS objects remain committed. End/change events are emitted only after successful terminal Chat persistence.
- Cancellation ownership: `InkToolExecutor::manages_cancellation` returns true for create/apply/prepare/render/export so the registry’s generic cancellation select cannot discard durable terminal results for these commit-capable operations. A registry-config regression assertion covers apply/prepare/export.
- Cross-call retry regression: a real DB test replays the same client operation in a later provider call/message/block, checks objects are not duplicated, and requires either a committed receipt bound to the retry block or an explicit link to the original authoritative receipt. A retry whose receipt belongs to an earlier block now returns `undo_available: false` plus `undo_receipt_message_id` / `undo_receipt_block_id`; no duplicate receipt row or timestamp is created.
