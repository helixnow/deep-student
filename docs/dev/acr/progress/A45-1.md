## 设计决策与偏差

1. **写路径裁决**：任务卡预期"features/template-management 的 store/lib"，但该域实际没有 store——`stores/` 目录为空，`lib/templateLibrary.ts` 是纯函数层；UI 的真实落库路径是 `@/data/ankiTemplates` 的 `templateManager` 单例。执行器动态 import 该单例，与 UI 完全同路径，未绕过任何域逻辑（sanitize/normalize/重读广播均复用）。
2. **OCC 裁决**：域自带 `version`（语义化版本字符串）+ `updated_at`。双层校验：(a) 能力入参可选 `expectedUpdatedAt`，与当前 `updated_at` 不符即 REVISION_CONFLICT，不发写请求；(b) 写请求经 templateManager 携带 `version` → 后端 `update_custom_template` 的 `expected_version` CAS（WHERE id AND version），失败错误（`optimistic_lock_failed` / "已被更新"）映射为 REVISION_CONFLICT 结构化回执。
3. **delete 可逆性裁决**：后端 `delete_custom_template` 对自定义模板做物理 DELETE（无回收站）；对内置模板做"停用 + user_deleted 墓碑"（不随升级导入复活，UI 无恢复入口）。两种路径都按不可逆处理：`reversible:false`、不注册 inverse，回执 message 明说语义差异（details 带 deleted/deactivated/isBuiltIn）。
4. **create 的可逆性**：物理删除刚创建的自定义模板是 create 的精确逆操作，故 createTemplate 标 `reversible:true` 并注册 `deleteTemplate` inverse（undo 统一 High 确认，符合纪律）。
5. **updateTemplateContent 大内容**：旧内容始终完整保存在 inverse args（可逆性优先）；超过 20k 字符时在 message 与 details（`inverseSnapshotChars` / `inverseSnapshotLarge`）如实标注负载体量，不截断、不静默。
6. **表面截断与实体校验**：surface 快照只投影前 50 条模板。清单未截断时，targetRef 指向未观察实体直接 ENTITY_NOT_FOUND；截断时放行至域层按权威数据判定（避免误杀 undo 场景中落在 50 条之外的新建模板）。
7. **observe 保持同步**：未把 observe 改成 async 去 join 域数据（避免影响既有 `systemAgentManifests.test.ts` 的同步断言与共享调用方）；OCC 令牌用 surface 已有的 `updatedAt`，version CAS 在执行器内兜底，效果等价。
