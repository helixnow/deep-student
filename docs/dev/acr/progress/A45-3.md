## 设计决策与偏差

1. **WorkbenchSearchHost 构造（依赖来源）**：AppsPanel 用 React hooks 构造宿主；agent 侧全部换成模块级单例——`appRegistry`（listLaunchableApps）、`i18next.t`（appName / untitledSessionTitle，先例：commandRegistry 直接 import i18next）、`commandRegistry.search(query, 'workbench', deps)`（searchCommands）、`windowStore` / `workbenchBus`（open 路径）。`deps` 是最小 `DependencyResolver`：读 getter 全接真实来源（isDarkMode 读 `documentElement.classList`，与 SkillsManagementPage 同法；getFocusedWorkbenchAppTypeId 读 windowStore；openCommandPalette 接 `openAppsPanel`，与 CommandPaletteProvider 的 workbench 改道一致），写动作（navigate/toggleTheme/switchLanguage）显式抛 `AGENT_DEPS_UNAVAILABLE`，让依赖它们的命令**结构化失败而非静默成功**。
2. **dstu 节点缓存**：provider 把 DstuNode 封在 open 闭包里拿不到，而 openSearchResult 需要 `node.type` 决定开窗应用 → 在 globalSearchProviders.ts 尾部追加 `createDstuProviderWithNodeCapture`（检索/映射与 createDstuProvider 完全一致，仅回传命中节点），manifest 侧用插入序 Map 缓存（上限 200）。未缓存的 dstu id 打开返回 `RESULT_EXPIRED`，提示先 globalSearch。
3. **chat 打开取 windowId**：`openChatInWorkbench` 返回 void，无法做权威回执 → 追加 `openChatInWorkbenchForAgent`（同一条 `openChatSession` 路径，返回 launch 的 windowId）。回执以窗口存在为准 acknowledged，message 里如实说明会话切换事件未逐条确认。
4. **execute 形参 `_ctx`→`ctx`**：globalSearch 需要 `ctx.signal` 做桥接取消级联，仅改名不改行为（已加 A45-3 注释）。
5. globalSearch 为纯数据面：`handled:true / changed:false / acknowledged:true`，与本文件 read 类语义（无视图态变更）一致；`mutates:false` 参照 agentRuntime 测试中纯读能力惯例（`reversible:false, idempotent:true`）。
