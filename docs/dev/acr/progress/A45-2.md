## 域调用链裁决（重试/取消到底走什么）

UI 的任务操作全部经 `src/features/anki/taskControl.ts` 薄门面 invoke Tauri 命令，Agent 写路径复用同一门面，未另起路径：

| 能力 | UI 入口 | 前端链 | Rust 命令 | 后端语义 |
|---|---|---|---|---|
| retryTask | FailedTasksPanel 逐段重试 | `controlDocumentTask({taskId, action:'retry'})` | `trigger_task_processing` | 仅接受 Pending/Failed/Truncated/Cancelled，防重入拒绝重复触发 |
| retryFailedTasks | SessionRow「重试失败」/ FailedTasksPanel「全部重试」 | `listFailedDocumentTasks` + 逐个 trigger（allSettled） | `get_document_tasks` + `trigger_task_processing` | 失败口径 = Failed/Truncated/Cancelled（与会话统计 failed_tasks 一致） |
| cancelSession | SessionRow「取消」 | `controlDocumentTask({documentId, action:'cancel'})` | `cancel_document_processing` | epoch+1 停调度 + 断流 abort，Pending/Processing/Streaming/Paused → Cancelled，不可逆 |

未暴露 pause/resume（超出本卡范围，域支持存在，留给后续轮次评估）。

## 不提供「创建任务」能力的证据

- `AnkiTasksApp.tsx` 全部 invoke：`list_document_sessions` / `get_anki_stats` / `get_prevent_sleep` / `set_prevent_sleep` / `recover_stuck_document_tasks` / `get_document_cards` / `delete_document_session` 等——没有任何创建会话/任务的命令；
- 空状态 CTA 仅 `onNavigateToChat?.('__new__')` 跳转 chat（`taskDashboard.goToChat`），即产品设计上创建入口就在 chat 制卡流；
- `taskControl.ts` 门面只有 pause/resume/cancel/retry 四种控制动作，无 create；
- 故 manifest 不注册任何 create 能力，并在 description 中明确「创建制卡任务请走 chat 制卡流，本面板不提供」。

## 设计决策与偏差

1. **表面扩展类型放在 `features/anki-tasks/agentSurface.ts` 而非 agentSurfaceRegistry.ts**：基础表面接口在 `agentSurfaceRegistry.ts`（非本卡名下文件）。利用 TS 返回值协变，AnkiTasksApp 的 snapshot 返回扩展形状仍满足基础 `TaskDashboardAgentSurface`；manifest 侧经 `taskDashboardAgentActions.ts` 的防御式 reader 读扩展字段，旧形状表面自动诚实降级。零跨界改动。
2. **失败分段的发现路径**：observe 保持同步、不在 observe 里 invoke。焦点会话失败分段由 AnkiTasksApp 的 effect 异步加载（仅 workbenchWindowId 存在且焦点会话 failedTasks>0 时；key 编码「会话 id+失败数+lastUpdated」避免轮询换引用导致重复拉取），Agent 流程 = focusSession → 再 observe 拿 task-segment 实体（loading 时诚实标注）→ retryTask 按 ref 操作，与用户「展开行看失败面板再重试」的心智路径一致。
3. **changed 语义与异步流转**：trigger/cancel 命令返回即域权威受理（后端状态机校验 + 防重入），故受理即 `changed:true`；写后重读若状态尚未流转，在 message 如实标注「状态流转为异步，稍后重新 observe」，不静默、不虚报终态。
4. **cancelSession 定为 high / idempotent:true**：中断在途生成不可逆（删除/不可逆 = high，ACR-4.5 §2）；重复取消无额外副作用（第二次落入 no-op）。retryTask/retryFailedTasks 定为 medium / idempotent:false（每次触发都会重新生成、可能产生新卡片）。
5. **i18n 无新增 key**：三个新能力全部不可逆、不注册 undo inverse，因此没有 undo 标签这类用户可见文案；回执 message/hint 面向 LLM，按 STANDARDS §2 直接写中文。`workbench.json` 两语未改动（无 key 需要成对补充）。
6. **targetRef 纪律**：retryFailedTasks/cancelSession 要求 targetRef + 观察清单成员校验（截断时豁免、交域层权威判定，对齐 A45-1）；retryTask 要求 task-segment targetRef，分段归属与失败状态由执行器 `getDocumentTasks` 权威校验（面板可能未展开）。
