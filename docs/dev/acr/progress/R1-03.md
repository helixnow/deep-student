## 设计决策与偏差
1. **watch 组装**：对齐 `builtin_resource_executor` L2333–2338——`VfsNoteRepo::get_note` → `note_to_dstu_node` → `DstuWatchEvent::updated`。拿不到 node 只 warn，不阻断工具成功结果。
2. **委托判定**：严格按任务卡——`clean|dirty|hot` 委托；`closed|frozen|disabled` 回落。桥 `Err` / `ok:false` / 缺 `state` 一律回落（不静默）。
3. **AgentOp kind**：`note_append`→`note_insert`；`note_replace`→`note_replace`；`note_set`→`note_set`。destructive：append=false，replace/set=true。
4. **anchor 形状**（供 R1-12 对齐，见下节）。
5. **apply_ops 超时**：任务卡写 60000ms（非 DESIGN §6 的动态预算）；本卡按任务卡。
6. **未改 notes_manager**：现有 `canvas_*` + VFS get_note 足够；若协调者希望回执带 `updatedAt`，可 R2 再加只读辅助。

### AgentOp anchor JSON（R1-12 对齐）

```json
// note_append 无 section
{ "position": "end" }

// note_append 有 section
{ "heading": "<section 标题>", "position": "afterHeading" }

// note_replace / note_set
{ "position": "end" }
// 若工具参数带 section，额外带 "heading"
```

完整 op 示例（append + section）：

```json
{
  "kind": "note_insert",
  "anchor": { "heading": "引言", "position": "afterHeading" },
  "payload": { "content": "..." },
  "destructive": false,
  "label": "追加内容到章节「引言」"
}
```

replace：

```json
{
  "kind": "note_replace",
  "anchor": { "position": "end" },
  "payload": { "search": "...", "replace": "...", "isRegex": false },
  "destructive": true,
  "label": "替换笔记内容（模式长度 N）"
}
```

set：

```json
{
  "kind": "note_set",
  "anchor": { "position": "end" },
  "payload": { "content": "..." },
  "destructive": true,
  "label": "设置笔记完整内容"
}
```

### probe → 委托 → 回落判定摘要
1. `acr_bridge_call(ctx, "probe", {target:{typeId:"note",resourceId}}, 3000)`
2. 桥 Err / ok=false / 无 state → 后端回落 + message 回落文案
3. state ∈ {closed, frozen, disabled} → 后端回落
4. state ∈ {clean, dirty, hot} → 组 AgentOp → `apply_ops`（destructive 按工具）
5. apply_ops 桥 Err / ok=false → 后端回落（避免双写：仅在委托失败时才写盘）
6. apply_ops 成功 → 回执 JSON 作 output，补 `message`/`mode`/`frontendDelegated`/`probeState`
