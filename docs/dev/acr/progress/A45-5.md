## 设计决策与偏差

1. **rotate 的 changed 判定**：React 状态异步提交，`surface.rotate()` 返回后同步 re-read 拿不到新角度；由于 90/180/270 增量对归一化角必然产生变化，changed 以「表面回执 + 增量语义」判定（执行前读角度用于 undo/details），与同文件 setZoom 的既有估算模式一致，未伪造 re-read。
2. **不暴露的 UI 能力及证据**：
   - 拖拽/方向键平移：本质是视口 scrollTop/Left 调整，无稳定语义锚点（“平移到哪”无实体可指），且 agent 无查看图片内容的收益路径，不暴露；
   - 「保存到本地」：走 OS 保存对话框（`fileManager.saveBinaryFile`），必须用户交互，非无头能力，不暴露；
   - `setFitMode`/1:1：`setZoom('fit')` 与 `setZoom(100)` 已语义覆盖，避免重复能力。
3. **scrollToMessage 架构**：workbench 侧不再感知列表内部实现，只消费 `messageListScrollRegistry` 的 handle；MessageList 内部按渲染模式分派（虚拟化 scrollToIndex / 直渲先 `setTailWindowExpanded(true)`），行挂载后以 DOM 实测在消息视口内精确对齐（不用 scrollIntoView，避免连带滚动 workbench 宿主窗口）。定位视为用户接管滚动（`userHasScrolledRef=true`），流式吸底循环不会立刻拉回底部。
4. **MESSAGE_NOT_FOUND 的重试**：冷启动期 store 数据可能未加载完（messageOrder 为空），故 not_found 也走短重试（0/250/800/1500ms）后才落定失败；对真正不存在的消息会多等约 2.5s，取舍偏向冷启动正确性。
5. **演出**：消息行追加 `data-agent-entity="chat:{messageId}"` 锚点，定位成功后 `agentFlash('chat', messageId, { scroll:false, scope:窗口根 })`；flash 失败不影响定位回执。

## 遗留给 R2 的事项

- 滚动 handle 的等挂载上限为 ~30 帧：单条消息渲染极重（超长 markdown/KaTeX）时可能超时报 VIEW_NOT_READY，可考虑改为 MutationObserver 等确定性挂载信号。
- 虚拟化模式对齐后，行内异步内容（图片/公式）再撑高会引起目标行偏移；如需像素级停靠可在挂载后追加一次 ResizeObserver 校正。
- MessageList 的 handle 注册未写组件级渲染测试（虚拟化在 jsdom 下需大量桩，本轮只写不跑难以保真），仅覆盖注册表与 workbench 消费侧；建议有实测条件时补一条长会话集成用例。
