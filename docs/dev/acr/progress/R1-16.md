## 设计决策与偏差

### content onActivation 实现形态
R1-12 已在 `content/register.ts` 实现 `handleNoteActivation`（`getNoteEditor(instanceKey)?.scrollToHeading(heading, level)`，签名见 `crepe/types.ts`：`(text, level, normalizedText?)`）。

因工厂 `createContentApp` 不接受 onActivation，无法按类型分段注入而不改工厂（工厂属 R1-13 边界）。本卡采用：

1. 保留 R1-12 的 `handleNoteActivation` 原样；
2. 新增 `createContentActivationHandler(typeId)`：
   - `typeId === 'note'` → 转调 `handleNoteActivation`；
   - 其余（textbook/exam/translation/essay/image/file）对 `scrollToHeading` → `console.warn`「v1 不支持」；
3. 对全部 `CONTENT_APP_DEFINITIONS` 统一赋值 `def.onActivation`（覆盖原先仅 note 挂载的写法，行为等价且扩展到其余类型）。

任务卡 ROUND1 写 `scrollToAnchor`，派发指令与 DESIGN/R1-12 对齐为 `scrollToHeading`（payload `{heading, level?}`）。

### pomodoro Driver
- op kind：`pomodoro_start` / `pomodoro_pause` / `pomodoro_resume` / `pomodoro_stop`（与派发指令一致）。
- onActivation action：`start` / `pause` / `resume` / `stop`（无 `pomodoro_` 前缀，对齐 app_command）。
- strictMode：Driver 路径 message 为 `JSON.stringify({code:'STRICT_MODE', hint:'严格模式下专注中不可暂停'})`；整批仅该失败 op 时 status=`failed`。
- probe 恒 `clean`（无脏文档概念；开窗判定由 StageManager/probe 模块负责）。

已导出；`stageManager.stop()` **当前未调用** `disposeAllDrivers()`（仅 clear drivers/queryProviders）。遗留 R2 接线。
