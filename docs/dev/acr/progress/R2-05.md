## 设计决策与偏差

### 1. block_type 持久化定稿
- **洞**：R1 仅前端流式 remap；`get_block_type_for_tool_static` / `tool_name_to_block_type` 仍落 `mcp_tool`，重启后走 generic/mcp 卡。
- **定稿**：
  1. Rust 写入路径：`workbench_*` → `block_types::WORKBENCH_OPS`（context + pipeline）；`history::is_tool_call_block` 纳入 `WORKBENCH_OPS`。
  2. 前端恢复兜底：`mcp_tool` + workbench toolName → `workbench_ops`（兼容旧库行）。
  3. 恢复时 `toolCallId = block.id`（DB 无 toolCallId 列；桥 runId 现为 block_id）。

### 2. runId vs toolCallId（与 R2-01 协商）
- 桥仍注入 `runId = ctx.block_id`（R1-01）；LLM `toolCallId` ≠ `block.id`。
- **前端**：撤销/联动用 `resolveWorkbenchRunId`：优先 `runLedger.hasRun` 命中的候选（toolCallId → block.id）。
- **权威对齐**仍需 R2-01：`ExecutionContext` 注入真实 tool_call_id，或约定 runId≡block_id 并改 STANDARDS 字面。本卡不改桥。

### 3. AgentTaskPanel 增列 — **否决**
- 面板职责是 todo 计划 / Runtime 沙箱 / Changes 文件写；workbench 导航与演出已有专用 `workbench_ops` 卡 + AgentStrip。
- 再增列会与工具卡双入口重复，且 workbench 块无稳定「变更摘要」结构可挂 Changes。
- **结论**：不实施；用户从消息流工具卡跳转/撤销即可。

### 4. 撤销失效
- `runLedger.hasRun(runId)` 为 false（LRU 淘汰 / 已 revert / 重启后内存账本空）→ 按钮禁用，文案 `undoExpired`。
- 账本本就不跨进程；重启后前端平面撤销不可用是预期。
