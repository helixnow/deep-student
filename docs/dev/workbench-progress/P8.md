## 遗留问题

1. **编辑视图缺脏状态查询接口**：`NotesCrepeEditor` 的 isDirty 是组件内部状态，Note/Essay/Translation ContentView 均未对外暴露。`contentDirtyRegistry` 已提供 `registerContentDirtyChecker(typeId, instanceKey, fn)` 挂点且 canClose 已接（脏→`window.confirm` 确认），但现有视图不会注册 checker，因此当前实际行为=直接放行关闭（与 legacy 标签页关闭行为一致，不回退）。需要后续在视图层（learning-hub 文件，非 P8 权限）接线。
2. **mindmap store 为模块级单例**（`useMindMapStore`）：多个 mindmap 窗口共享同一份文档状态。isActive（focused）映射保证同一时刻只有焦点窗口接管键盘/加载/标题同步（与 legacy 多标签行为一致），但两个 mindmap 窗口同时可见时，非焦点窗口显示的是其最后渲染画面，焦点切换会触发 store 切换文档。窗口级 store 隔离属后续改造。
3. **finderStore 也是全局单例**：files 是 single 实例所以无冲突；但 workbench 模式下若 legacy learning-hub 页面同时挂载（不应发生），二者会共享导航状态。
4. **canClose 用 `window.confirm`**：非 简洁风格对话框。因 canClose 是非 React 上下文回调，首版用原生 confirm；后续可由 P3/P11 提供壳级确认 UI。
5. `LearningHubSidebar` 内部的 `useCommandEvents` 以 `useViewVisibility('learning-hub')`（legacy currentView）作为启用条件，workbench 模式下命令面板的"新建文件夹/聚焦搜索"事件不会到达 files 窗口——属 P11 导航迁移范围。
