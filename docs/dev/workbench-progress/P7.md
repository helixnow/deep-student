| 单例 | 影响 | 适配 |
|---|---|---|

### DoD 人工验证路径（等 P11 接线后执行）

1. 开启 `desktop.workbenchMode` → Dock 点 chat（或调 `launchNewChatSession()`）开窗 A；
   再 `launchNewChatSession()` 开窗 B，两窗左右平铺。
2. 窗 A 输入“1+1=?”发送、窗 B 输入“2+2=?”发送：各自消息流独立滚动，输入框内容互不串扰；
   A 流式期间 B 可正常输入发送（AdapterManager 多会话保活）。
3. 聚焦窗 A，从资源库注入上下文 → 引用应出现在 A 的输入栏（currentSessionId 指针跟随焦点窗）。
4. 关闭窗 A → 重新 `workbenchBus.launch({typeId:'chat', instanceKey:'<A的sessionId>', reason:'api'})`：
   历史消息完整恢复（关窗≠删会话）。
5. 窗 B 流式输出中把 A 最大化盖住 B（B 转 background）：B 的 token 不丢，重新聚焦 B 立即补渲全文。

## 遗留问题

1. **sessionManager LRU（maxSessions=10）与多窗共存的冲突**：同时打开 >10 个不同会话的 chat 窗口
   （含 frozen 壳重开等场景）时，最旧的非流式会话 store 会被淘汰，`finalizeEviction` 销毁 adapter
   不检查 AdapterManager refCount，仍挂载的后台窗口会丢事件监听（视图仍在，需重新聚焦触发重连）。
   修复需改 `sessionManager.evictLRU`（跳过 refCount>0 的会话）或提高 maxSessions，属 chat 文件，超出 P7 权限。
2. **scrollToMessage 为 best-effort**：MessageItem 无 message id DOM 锚点（chat 文件不可改），
   直接渲染模式（≤80 条消息）按 role="log" 子节点索引精确定位；虚拟化长会话（>80 条）与渐进渲染
   首帧窗口期无法定位（console.warn 后放弃）。彻底解法：在 MessageItem 根节点加 `data-message-id`
   或 MessageList 暴露 scrollToIndex 命令 API（建议后续由拥有 chat 文件写权限的批次补）。
3. **不可见窗口流式降频只有 `silky` 档（commit gate 48ms）**：现有 StreamPreferences/streamingSmoothing
   没有 ~500ms 级低频档（设计文档 §5.1 的目标值）。加新 preset 需改
   `src/features/chat/components/renderers/streamingSmoothing.ts`，已按任务书要求记录遗留。
   实际影响有限：background 窗口由 WindowBody `content-visibility:hidden` 兜底，绘制成本近零，剩余为 React commit 成本。
4. **快照恢复 instanceKey=null 的 chat 窗**：Dock 无 key 启动的窗口自动建会话，但窗口壳的 instanceKey
   恒为 null（windowStore 无改 key API），应用重启后该壳恢复时会再建一个新会话。规避：入口尽量走
   `launchNewChatSession()`（先建会话再 launch，instanceKey=sessionId）。
5. **`autoCreatedSessionByWindow` Map 常驻**：按 windowId 记忆自动建的会话（服务 frozen→唤醒），
   窗口关闭后条目不清理（无法在组件内区分 close 与 freeze）。每条仅两个字符串，量级 = 无 key 启动的窗口数，可忽略。

## 需要接线代理（P11）处理的事项

1. **Dock pinned 的 chat 项建议接 `launchNewChatSession()`**（或 launch 时带 instanceKey）；
   直接 `launch({typeId:'chat'})` 也能用（窗内自动建会话兜底），但见遗留 4 的快照限制。
2. **legacy 导航迁移**：`CHAT_V2_SET_INPUT` / `navigate-to-session` / 命令面板 CHAT_* 事件在 workbench
   开启时改走 `workbenchBus.activate({typeId:'chat', instanceKey, action:'setInput'|'focusInput'|'scrollToMessage', payload, fallbackLaunch})`；
   activate 对刚 fallbackLaunch 的窗口，setInput 已内置 store 就绪重试（最长 ~1.5s），无需额外等待。
3. **页面级事件宿主在桌面层挂载一次**（不能逐窗挂，也不在本代理归属内）：
   `AnkiPanelHost`（open-anki-panel）、`CHAT_OPEN_ATTACHMENT_PREVIEW`（建议路由为 launch 对应资源窗）、
   `context-ref:preview`、`pdf-ref:open`（建议 activate textbook/file 窗后派发 pdf-ref:focus）——
   可与 P9 eventHub 对齐。
4. **`chat-v2:sessions-updated` 事件**：launchNewChatSession / 窗内自动建会话后已派发，files 型会话

5. **registerAll**：import `@/features/workbench/apps/chat/register`（模块加载即幂等注册），或调
