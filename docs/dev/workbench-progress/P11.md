## index 出口评估（P10 遗留 1）

结论：**保留现状 + 深路径豁免约定**，不拆分。理由：
1. workbench 全部重 UI（含 chat 应用）均为 React.lazy + 动态 import，index 的静态部分只有
   core 逻辑与轻组件壳，chat store 全链不会因 re-export 被静态拉入（newSession 的
   createSessionWithDefaults 是唯一较重静态依赖，仅在 index 被消费方 tree-shake 失败时引入）；
2. 已确立的实践：外部业务模块（settings 页、App.tsx）按 P10 先例使用深路径导入轻模块
   （core/workbenchBus、core/materialTier、core/legacyNavigationMap、components/WallpaperLayer）；
   WorkbenchDesktop lazy chunk 内部自由使用 index；
3. 拆分 index 需改动全部十个代理的导入约定与既有测试，收益（首包减小）已由 lazy 分支
   （App.tsx 仅在开关开启时 import WorkbenchDesktop chunk）实现。

2. **Dock 直接点击 chat（无实例）产生 instanceKey=null 壳**：窗内自动建会话可用，但该壳
   重启恢复时会再建新会话（P7 遗留 4）。改善方向：DockItem 对 chat 特判走
   launchNewChatSession，或 windowStore 增加改 key API（涉及冻结契约，留后续批次）。
3. **pdf-ref:open 无 sourceId 时的深度解析未迁移**（legacy 在 ChatV2Page 扫描当前会话附件
   推断 PDF）；workbench 下 console.warn 忽略。见导航迁移清单暂缓节。
4. **命令面板 openFileFromPalette 在 workbench 开启时无效**（等待 learning-hub
   OpenResourceHandler 4s 后放弃）——需在 command-palette 侧按 bus.isEnabled() 分支，
   本批次未动 command-palette 文件。会话直达（navigate-to-session）已可用。
