## 已完成

- `core/pointerEngine.ts`（新增）：框架无关指针引擎 `WindowPointerEngine`。
  Pointer Events + setPointerCapture；拖动/八向缩放；pointermove 只暂存坐标、
  rAF 合帧后回调 `onFrameChange`（消费方直写 DOM）；move 手势同帧做
  `hitTestSnapZone` 命中并去重回调 `onSnapZoneChange`；松手 `onCommit(frame, zone)`
  （up 前未消费的最后一个点同步补算）；Esc / pointercancel / lostpointercapture /
  window blur 统一回退：`onFrameChange(startFrame)` + `onCommit(startFrame, null)`；
  minSize clamp（对边固定语义）；move 边界 clamp（顶不出界、四周保留可抓回带
  `MOVE_KEEP_VISIBLE_X/Y`）。
- `components/window-shell/useWindowPointer.ts`（新增）：冻结接口
  `WindowPointerCallbacks` 的 hook 封装。全 ref 透传、返回终身稳定的
  `startMove`/`startResize(edge)`/`cancel`/`isDragging`/`activeGesture`，自身 0 state；
  minSize 从 `appRegistry.get(typeId)` 取（兜底 `FALLBACK_MIN_SIZE` 320×240）；
  desktopSize 经 `useWindowStore.getState()` 非响应式读取；卸载 dispose。
- `core/snapZones.ts`（新增）：`hitTestSnapZone(pointer, desktopSize)` 纯函数——
  四角 64px（优先）→ 四分屏；左/右缘 24px → 半屏；顶缘 24px → maximize；
  桌面外 → null。常量 `SNAP_EDGE_THRESHOLD`/`SNAP_CORNER_THRESHOLD` 导出。
- `core/tiling.ts`（基线重写为完整版，`computeTiledFrame` 签名不变）：
  精确 margin 几何（外缘 m + 中缝 m，availW = W−3m，整数互补分割：
  left.x+left.w+m === right.x，right 右缘贴外缘 m，四分屏两轴同理，无缝隙无重叠）；
  ratio 只作用于 tiled-left/right 对（四分屏固定 0.5）；
  新导出 `zoneToDisplayMode`、`clampTilingRatio`（0.2–0.8，非法回退 0.5）、
  `tilingPairKey`、`DEFAULT_TILE_MARGIN=8`、`MIN/MAX_TILING_RATIO`。
- `components/SnapPreview.tsx`（新增）：`zone` prop → 轮廓层。`wb-snap-preview`
  类名契约（材质由 P4 实现）；独立 fixed 层 + pointer-events:none；120ms fade-in/out
  （仅 transform/opacity 过渡，遵守 §6.5）；zone→null 时保留最后轮廓 fade-out 后卸载；
  可选 `margin`（缺省 8）与 `desktopOffset` props。
- `components/window-shell/useTilingDivider.ts`（新增）：
  `useTilingDivider(leftId, rightId, options?)`——中缝 pointerdown 捕获、rAF 合帧、

## 遗留问题

- `useTilingDivider` 的 ratio 换算为 `(clientX − offsetX) / desktopW` 的一阶近似，
  未扣除 margin 造成的 ±1.5m 偏差（8px margin 下 ≤ 12px，中缝拖拽体感可忽略）；
  如需像素级精确可在接线时传入 margin 参数扩展。
- SnapPreview 的 fade 过渡以内联 style 实现（120ms、仅 transform/opacity），
  材质（描边/填充色）完全交给 P4 的 `wb-snap-preview` 类；若 P4 希望统一由 CSS
  控制时序，可协商去掉内联 transition。
- pointerEngine 的 window `blur` 取消策略较保守（Alt+Tab 即回退拖动）；
  与 macOS 行为一致，但如产品层想要"失焦保持拖动"需调整。

## 需要接线代理（P11）处理的事项

- `WindowShell`（P3）拖动 commit：`onCommit(frame, zone)` 中 zone 非 null 时应调
  `zoneToDisplayMode(zone)` → `store.setDisplayMode`；zone 为 null 时 `store.moveWindow`。
  从 tiled/maximized 态开始拖动时，`getFrame` 应传当前视觉 frame
  （`computeTiledFrame` 结果），并在拖动开始时恢复 floating（macOS 拖离恢复语义，
  由 P3/P11 在 shell 层完成）。
- `SnapPreview` 挂在 WorkbenchDesktop 顶层，`zone` 来自当前拖动窗口的
  `onSnapZoneChange`；桌面区非视口原点时传 `desktopOffset`（同样适用于
  `useWindowPointer.getDesktopOffset` 与 `useTilingDivider` options）。
- tileMargins 设置：`computeTiledFrame` 的 `ctx.margin` 与 `SnapPreview.margin`
  由设置读取后传入（关闭 = 0，开启缺省 `DEFAULT_TILE_MARGIN`）。
- 左右平铺对的 ratio：渲染 tiled-left/right 窗口时用
  `tilingRatios[tilingPairKey(leftId, rightId)]` 作为 `ctx.ratio`（左窗）；
  右窗传同一 ratio（computeTiledFrame 内部自动取补）。中缝元素绑
  `useTilingDivider(leftId, rightId)`。
- 拖动期间对 `visible` 档窗口挂起降频渲染（§5.4）属于 Desktop/scheduler 协作，
  引擎已保证不产生 React 渲染，无需额外接口。
