## 遗留问题

1. **遮挡计算的平铺 margin**：`computeOcclusion` 第三参 `margin` 默认 0。P11 接线 tileMargins 设置后，若渲染层用非 0 margin，调 scheduler 时应保持一致（当前 scheduler 内部固定传默认 0；margin>0 只会让上层窗口"更小"，误差方向是宁可 visible，符合设计 §11 的降级取向）。
2. **tiled-left/right 的 ratio 未参与遮挡矩形**：遮挡计算对 tiled 对使用默认 0.5 分割。非 0.5 比例下极端布局可能把全遮挡误判为 visible（同样是"宁可 visible"方向，不会错杀）。如需精确可在 P11 接线时把 tilingRatios 传入扩展。
3. **scheduler 未自动持久化**：`saveSnapshot()` 的调用时机（窗口增删/移动提交/比例变化后）按任务书归 P11 在 WorkbenchDesktop 装配时订阅触发；P1 只提供防抖 API。
4. `snapshot.ts` 内置了轻量 settings 读写（同 `get_setting`/`save_setting` 命令 + localStorage 回退），未直接 import `utils/settingsApi`——后者传递依赖过重（heic2any/i18n/debugLogger 等），会拖累 workbench chunk 与测试。行为语义一致。

## 需要接线代理（P11）处理的事项

1. WorkbenchDesktop 启动时：`loadSnapshot()` → `store.hydrate(snap.windows, snap.tilingRatios)` → `startScheduler()`（返回 stop 函数，模式关闭/卸载时调用）。
2. 订阅 store（windows/tilingRatios 变化）→ 调 `saveSnapshot()`（内部已 2s 防抖）；模式关闭/应用退出前调 `flushSnapshot()` 立即落盘。
3. Dock 固定区（P5 `useDockPinned`）就绪后调 `registerDockPinnedProvider(() => pinned)`，否则快照 dockPinned 恒为 `[]`；恢复时把 `snapshot.dockPinned` 交给 Dock。
4. 快照恢复时对 `instanceKey` 指向已删除资源的窗口做丢弃（设计 §7；需要业务侧存在性检查，内核不感知资源）。
5. 若 tileMargins 设置启用非 0 margin，评估是否需要把 margin 传入 scheduler 的遮挡计算（见遗留问题 1）。
6. `snapshot.wallpaper` / `snapshot.materialTier` 字段 sanitizer 已支持，写入方（P4/P10 的设置）如需入快照，可扩展 buildSnapshot 的采集来源（当前只采集 windows/dockPinned/tilingRatios）。
