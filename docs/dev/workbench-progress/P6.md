## 遗留问题

1. **窗口壳定位方式假设**：ExposeOverlay 假设窗口壳静止时不依赖内联 `transform` 定位（以 left/top/width/height 落位，transform 仅拖拽过程瞬态使用，符合设计 §5.4）。若 P2/P3 最终以常驻 transform 定位窗口，俯瞰的 transform 覆盖会破坏基准位置，需要在接线时改为组合矩阵或包装层方案。
2. 俯瞰期间若窗口集合变化（新开窗）会按缓存源矩形重排一次；极端场景（俯瞰中窗口被程序最小化）该窗的 transform 会保留到退出俯瞰时统一恢复，无泄漏但视觉上不额外处理。
3. Ctrl+W 的"可配置"目前是 hook 选项 `enableCloseWindow`，设置项存储与 UI 归 P10/P11 接线。
4. 俯瞰命中层 zIndex 用 2147483000 内联值压过所有窗口；`wb-expose-backdrop` 层 zIndex=5（假设窗口 zIndex ≥ 10、壁纸层 < 5）。若 P4/P11 的层序不同需对齐。
5. 预存量测试 `tests/vitest/workbench/window-titlebar.test.tsx`（P3 所属）有 1 个与 P6 无关的失败（pointerdown spy），未触碰。

## 需要接线代理（P11）处理的事项

1. **WindowShell 根元素必须携带 `data-wb-window-id={win.id}`**（ExposeOverlay 依赖此属性定位窗口 DOM 施加缩放；缺失时该窗不参与俯瞰动画但缩略命中区仍可点击聚焦）。
2. WorkbenchDesktop 根部：挂 `useWorkbenchShortcuts({ enabled: workbenchMode, enableCloseWindow: 设置值 })`，并渲染 `<ExposeOverlay />` 与 `<WindowSwitcher />`（两者自读 store，无必传 props；应渲染在桌面容器内——ExposeOverlay 以自身 offset 容器为坐标系）。
3. 层序确认：壁纸层 zIndex < 5 < 窗口（≥10）；俯瞰命中层/切换器使用超高内联 zIndex。
4. Dock 端点触发俯瞰可直接调用 `useWorkbenchOverlay.getState().toggleExpose()`（已从 index.ts 导出）。
5. P10 设置页快捷键清单：`import { listWorkbenchShortcuts } from '@/features/workbench'`，条目含 `keys`（如 `Ctrl+Alt+←`）、`descriptionKey`、`defaultDescription`、`configurable`。
