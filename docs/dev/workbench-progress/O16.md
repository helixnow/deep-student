## 已完成（实现细节）

1. **三段接力的加载骨架**（消灭空白/转圈）：
   - `register.render = React.lazy(ChatWindowFrame)`：先导 chunk 只含 React + 骨架屏
     （加载近即时）；`ChatWindowFrame` 内层再 `React.lazy(ChatAppWindow)` 二段加载
     重代码（ChatContainer 全家桶），期间 Suspense fallback = 气泡骨架屏；
   - `ChatAppWindow` 无 instanceKey 自动建会话的等待态同样渲染骨架
     （statusText='正在准备会话…' 供屏幕阅读器）；
   - 骨架结构刻意复刻 legacy `chat-loading-shell`（用户右气泡 / 助手头像+行 ×2 组 +
     底部输入栏面板），并对齐 `--chat-thread-max-w` 线程宽度契约——
     「wb 骨架 → legacy 冷启动骨架 → 真实内容」三段视觉连续无跳变；
   - 骨架挂载后延迟 120ms 才淡入（wb-kf-fade-in + --wb-motion-quick/--wb-ease-swift），
     快速加载在可见前即被替换 = 等效不显示；骨骼脉冲为纯 opacity 循环，
     `--wb-chat-bone-i` 驱动 80ms/骨骼错峰。
2. **缩放稳定滚动锚点**：`useResizeScrollAnchor(rootRef)`
   - passive scroll 监听持续记录消息 viewport 的距底距离；ResizeObserver 观察窗口
     内容根节点，几何变化帧在「布局后、绘制前」把 scrollTop 校正回距底不变的位置——
     吸底（距底≈0）时钉死底部、上翻阅读时读到的内容不漂移；直写 DOM 不进 React state；
   - viewport 解析从 `[role="log"]` closest 到 `[data-overlayscrollbars-viewport]`
     （native 档 `.scroll-area--native`），避免误中窗内其他滚动区；空态静默跳过；
   - 配套 `overflow-anchor: none`（仅 wb-chat-surface 作用域）关闭浏览器原生
     顶部锚定，防止与距底锚定双重补偿抖动；
   - 与 MessageList 内部逻辑正交：其吸底 rAF / prepend 补偿只在内容变化时写
     scrollTop，本 hook 只在几何变化时写。
3. **流式降频不骤停**：`useDeferredStreamPreset(isVisible)`
   - 可见→不可见延迟 800ms 才下档 balanced→silky：拖窗掠过 / 焦点快切等瞬时遮挡
     不再打断流式节奏；期间可见性回归则取消下档定时器；
   - 不可见→可见立即回 balanced：缓冲 token 以全速档 charsPerSecond=480 +
     backlogBoost 平滑补渲（streamingSmoothing 自带消化逻辑），而非整段跳出；
   - 挂载即不可见（后台恢复窗）直接从 silky 起步。
4. **窄窗紧凑布局**（容器查询，按窗口宽度而非屏幕宽度）：
   - `.wb-chat-surface { container-type: inline-size; container-name: wb-chat }`；
   - ≤640px：把 legacy 对齐契约成员（消息行/输入栏/空态/回底按钮共享的
     `px-4 md:px-8`）统一压回 1rem——宽屏上的窄窗不再错误吃到 md: 的 2rem 大边距，
     且全员同步保持左右对齐；空态标题从 vw 基准改 cqi（容器宽度）基准；
     空态 composer 栈留白对齐 legacy 移动端档；
   - ≤520px（minSize.w=480 的极窄档）：进一步压到 0.75rem。
5. **焦点/输入隔离视觉确认**：
   - surface 根节点输出 `data-wb-chat-active`（isActive 直通）；
   - 非焦点窗输入区（composer）淡化至 opacity 0.6，焦点回归经
     `--wb-focus-duration/--wb-focus-ease`（O1 三态 token）过渡点亮 =
     「打字会进这个窗」的 macOS 非 key window 语义；
   - 实现细节：不能淡化 `.chat-composer-motion-frame` 本身（其 legacy 入场
     animation fill:both 终帧 opacity:1 永久压过普通声明），淡化其内层包装 div。

## 视觉与交互决策（供人工复核）

| 决策 | 取值/理由 |
|---|---|
| 骨架屏延迟淡入 | 120ms 延迟 + quick/swift 淡入；快加载零闪烁，慢加载及时出现（与 legacy chat-loading-shell-defer 同语言） |
| 骨架脉冲 | 1.7s opacity 0.5⇄0.95 循环、每骨骼 80ms 错峰；reduced-motion/minimal 静态 opacity 0.6 |
| 骨架布局 | 顶对齐 + 复刻 legacy 骨架比例（h-16 w-2/3 用户泡等），三段骨架接力无跳变 |
| 降频下档宽限 | 800ms（盖住拖拽遮挡/切窗动画的典型时长）；升档 0ms |
| 缩放锚点策略 | 保持「距底距离」不变（chat 自底向上阅读语义）；吸底=钉底，上翻=位置不动 |
| 窄窗断点 | 容器查询 640px（紧凑）/ 520px（极窄）两档；只压水平留白不动字号排版（空态标题除外，vw→cqi） |
| 非焦点输入区 | opacity 0.6 + 焦点三态 token 过渡；只淡化 composer，消息流不淡化（保持可读） |

## 需 O20 reconcile 事项

1. **WindowBody 通用 Suspense 转圈仍有一瞬**：先导小 chunk（ChatWindowFrame）加载
   期间显示的仍是 WindowBody（O9 名下）的转圈 fallback，通常 <1 帧网络往返。
   若 O9/O20 想彻底消灭，可让 WindowBody 支持 per-app fallback 注入（O16 已就绪骨架组件可直接复用）。
2. **`.md\:px-8` tailwind 类名依赖**：窄窗紧凑布局通过覆盖 legacy 共享对齐契约类
   `px-4 md:px-8`（`ChatSessionSurface.css` 容器查询内，作用域限
   `[data-wb-chat-session]`）。若 legacy chat 调整该 padding 契约或 tailwind
   前缀策略变化需同步；specificity (0,2,0) 高于 utility (0,1,0)，未用 !important。
3. **`overflow-anchor: none` 作用域**：仅 wb-chat-surface 内的滚动 viewport 关闭原生
   scroll anchoring（由 useResizeScrollAnchor 全权接管）。legacy 全屏 Chat 页不受影响。
4. **曲线 token 引用**：已用 O1 motion.css 的 `--wb-motion-quick`、`--wb-ease-swift`、
   `--wb-focus-duration/-ease`（均带 fallback，O1 未加载也可渲染）。入场 keyframes
   用本地 `wb-chat-skeleton-in`（与 O1 `wb-kf-fade-in` 等价）——引用外部 keyframes
   在 motion.css 未加载时会让骨架停在 opacity:0，故保留本地副本；O20 如统一可替换。
5. **容器查询兼容基线**：WebView2/WKWebView 均支持 `@container`/cqi；WebKitGTK 老版本
   不支持时优雅降级为「不紧凑」（保持基础布局，不破坏）。
6. **既有遗留不变**（P7 记录，仍有效）：sessionManager LRU 与 >10 窗冲突、
   scrollToMessage best-effort、快照恢复 instanceKey=null 再建会话。
7. **workbench 全套件 9 个失败**与本代理无关（windowStore/snapshot/scheduler/
   WindowSwitcher/EmptyDesktop，属 O8/O10/O11/O14 并行在途改动），O20 门禁时复核。
