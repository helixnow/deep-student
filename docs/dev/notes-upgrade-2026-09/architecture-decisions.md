# WP00 — Notes 架构决策

日期：2026-09-21。依据：`c7248a222 / v0.9.63`，见 [baseline](baseline.md)。

状态：**本轮设计选择，待后续 WP 实现和验收**。本文出现的新字段、命令、协议和表都是建议，不表示当前代码已经存在。短期保持 Crepe/Milkdown，不扩展到更换编辑器或协同编辑引擎。

## ADR-01：短期 Markdown 是正文的单一权威格式

**选择**：保留 `notes → resources.data` 的 Markdown 正文。ProseMirror 文档是内存编辑模型；块索引、搜索、反链、摘要是派生数据；不另建可独立修改的 JSON AST 权威副本。

“完整文档版本”定义为一次原子提交得到的以下组合：

```text
noteId + versionId + parentVersionId + restoredFromVersionId?
title（纯文本）+ 完整 contentMd（含稳定块标记）+ tags + props
contentFormat + formatVersion + serializerVersion
assetRefs（版本内附件清单）+ source + createdAt
```

正文以 Markdown 为权威，标题／tags／props 仍是独立文档元数据；它们与正文一起进入历史快照，不要求把全部元数据塞进正文 YAML。收藏、目录归属、窗口大小、光标、滚动位置是工作区状态，恢复历史默认不改这些状态。`updated_at` 是当前写入令牌，不是历史排序或不可变身份。

完整版本必须含全文，包括未加载后缀、折叠内容、代码、公式和未知语法。不能只保存可见块、行 diff、AI 修改段落或旧 resource_id。diff 只是预览表示。

**兼容要求**：支持语法允许序列化产生语义等价的规范化（例如列表符号、空行）；未知语法及未编辑原文不能静默丢失。仅打开或切阅读模式不触发重写。原始文本与规范化输出不同的情况必须由样本说明，不能拿 `trim()` 后相等掩盖内容损失。

**原因**：现有保存、导入导出、AI、全文检索、长文窗口都以 Markdown 为基础。双权威会扩大这次改造范围并产生来源冲突。当前内容哈希对 Markdown 字符串做寻址是已有用途，可保留；新增版本身份用 ID／父版本关系，不对含 HashMap 的整个 envelope 序列化后哈希。

## ADR-02：逐页 opt-in，迁移前保存旧版，旧客户端不能写新格式

**选择**：在专用 schema 字段中记录格式状态，建议 `notes.content_format`（缺省 `markdown-legacy`）及 `format_version`，不能复用用户可编辑的 props。历史功能启用与块格式升级分开：legacy Markdown 也能先拥有完整快照；用户确认某页升级后才写入新块标记。

迁移顺序：读取完整页及当前写令牌 → 展示兼容性结果 → 用户对本页 opt-in → 同一事务保存 legacy 基线版本和升级版本并切换当前指针。异常整体回滚；不能先改格式标识再补正文。打开旧页、后台索引、渲染都不能隐式批量迁移。

| 输入／客户端 | 读取规则 | 写入规则 |
|---|---|---|
| legacy 页 + 新客户端 | 按原 Markdown 读 | 保持 legacy，直到本页 opt-in；可记录历史 |
| 已 opt-in 页 + 支持该版本的客户端 | 新解析器读完整格式 | 必须携带 expectedVersionId；块标记保持身份 |
| 未知更高 formatVersion | 展示原始 Markdown／兼容只读内容 | 拒绝结构化重写；允许原文导出 |
| 带未知 HTML/directive/front matter 的 legacy 页 | 保留原文，提示不支持编辑的片段 | 在无损能力证明前保持 legacy 或源码操作，不能把未知部分丢掉再保存 |
| 已 opt-in 页 + 未升级客户端／设备 | 老二进制不具备新字段判断能力 | **不能声称只加字段即可保护**。开放同步前必须有客户端能力门槛／拒写接入；未完成时只做本地受控 opt-in |

后退不是把格式号清空：先保存升级后当前版本，再显式导出兼容 Markdown 副本，或在仍支持新格式的客户端中恢复升级前版本。清除块标记会失去实时块定位，必须说明；固定历史引用仍指向原版本。恢复 legacy 版本是新提交且恢复其格式，不覆盖历史。旧版本已经被迁移删除的数据不能从本次升级中“恢复”。

## ADR-03：标题是纯文本，稳定块 ID 不依赖标题或位置

### 标题

页面标题与 callout/toggle 标题都采用单行纯文本，不渲染行内粗体、链接或公式。正文中的 Markdown heading 仍允许既有行内语义，二者不能混淆。页面标题保留现有最大 500 字符后端约束。

从富文本导入标题时明确转换成显示文本（例如 `**结论** [来源](https://example.invalid)` → `结论 来源`）；保留迁移前快照。用户在纯文本标题输入框手打 `**结论**` 时，这些符号是字面字符，不应自动删除或渲染。转换器须正确转义序列化标记，防止第二次解析再次变成富文本。

当前 callout remark 会递归提取文本，toggle/callout schema 的 title 是字符串 attrs，但不能据此宣称上述所有导入／输入／往返规则已经统一实现。F04 固定这些差异。

### 稳定块身份

**选择**：新格式的 MVP 先给每个顶层可寻址块一个不透明 ID；列表、表格、callout/toggle、代码和 HTML 容器作为完整顶层块寻址。容器内部精细寻址放到后续格式版本，不把位置路径伪装成稳定 ID。身份是 `(noteId, blockId)`，固定历史身份是 `(noteId, versionId, blockId)`。

建议以独立 HTML 注释承载 ID，作为 Markdown 权威内容的一部分：

```markdown
<!-- ds:block-id=b_f06_intro -->

这是一段正文。
```

该语法是 **WP00 提案**，当前 Crepe 没有保留它的承诺。实现需在 Markdown AST 转换和 schema attrs／serializer 两端成对接线，并让块索引与标题导航跳过标记；不能只增加 DOM `data-*` 或运行时随机 ID。注释只在根级、非代码区绑定紧随的顶层块；围栏内相同文本是字面内容。无法无损保留的页不能 opt-in。

| 编辑动作 | 身份规则 |
|---|---|
| 修改内容、改标题、块类型转换、同页移动 | 保留 ID；位置、字数和 heading slug 不参与身份 |
| 新块、复制块、跨页复制 | 分配新 ID；不按相同内容去重 |
| 分裂 | 原第一部分保留 ID，新部分新 ID |
| 合并 | 按原文顺序第一块保留 ID；其余 ID 在当前版本不存在，不能悄悄转发到另一块 |
| 删除 | 当前定位显示“块已删除”；历史版本仍可定位原块 |
| 恢复历史 | 新版本携带被恢复版本的块 ID；恢复前的历史保持可读 |
| 源码编辑产生重复 ID | 已知复制操作立即换新；外部导入中的歧义必须在导入预览中修复或拒绝升级，不默默选一个目标 |

随机 ID 仅在创建身份时产生，不在每次加载时产生。新格式保存必须检查本页 ID 唯一性和缺失；兼容旧调用方时不能用全文相似度悄悄重新绑定引用。

## ADR-04：历史用不可变的完整快照，恢复创建新版本

**选择**：新增独立 `note_document_revisions`，正文直接存 `content_md TEXT NOT NULL`。相较“让旧 resources 永久存活”，这是当前 Repo 主动清理旧资源条件下最小的可控改造；仍可继续回收旧当前资源和索引。这里的历史快照是旧状态的不可变记录，不是另一份可编辑正文。

建议数据契约（示意，不是可直接投产的迁移）：

| 字段／对象 | 约束 |
|---|---|
| `version_id` | 不透明唯一 ID；不使用内容哈希作版本 ID |
| `note_id, parent_version_id, restored_from_version_id` | 所属笔记、前一当前版本、恢复来源；恢复目标必须属于同一笔记 |
| `title, content_md, tags_json, props_json` | 同一事务的完整文档状态；空正文合法；props 保持现有标量对象约束 |
| `content_format, format_version, serializer_version` | 原始格式与解释版本；不能用应用 semver 代替文档格式版本 |
| `asset_refs_json, source, created_at` | 附件清单、来源（editor/ai/import/restore/migration 等）、记录时间；附件内容规则见 ADR-06 |
| `notes.document_version_id` | 当前已提交文档版本指针；存量默认为 NULL，首个受控写入时保存基线再前进 |
| 历史列表索引 | `(note_id, created_at, version_id)`；游标分页，时间同毫秒仍有确定顺序 |
| 固定／保留记录 | 与不可变正文分离；最小可持久化版本 pin，支持来源 owner 后再做精确解除 |

不把历史外键绑到临时当前 resource_id。父版本允许成为已清理的血缘标识，读取完整版本不依赖重放父链。版本内容不能原地改写。

### 保存事务

1. 同一 SQLite 连接／事务读取 note、完整资源正文和当前版本指针；校验 expectedVersionId（新接口必传，首次基线用明确的旧 updated_at CAS）。
2. 对首次接入页保存一次完整 baseline。仅变动 updated_at／索引状态不生成内容版本；title/tags/props 的真实改变也要生成版本。对象字段用结构比较，禁止普通 JSON 序列化相等判定。
3. 按旧路径生成当前资源，写入完整新版本、更新 notes 指针／元数据、当前出链和附件引用，一起提交。失败不得出现“笔记已写但版本没写”的成功回执。
4. 返回 note + 新 versionId + updatedAt；UI 只确认对应版本已保存。索引异步任务不改变这个版本身份，任务失败可重试。

Repo 的 `update_note_with_conn` 已有 SAVEPOINT，可扩展这条事务；metadata 路径需加入同等事务边界。不能在前端先调“创建历史”再调“保存”，也不能只覆盖 `notes_update` 而漏掉 DSTU、Canvas、metadata、ZIP overwrite 和同步写入。

### 最小接口与恢复

建议命令：`notes_history_list(noteId, cursor, limit)` 返回摘要；`notes_history_get(noteId, versionId)` 返回完整只读快照；`notes_history_restore(noteId, versionId, expectedVersionId)` 返回新当前版本。名称均未实现。

恢复步骤：先处理当前未保存草稿（保存／保留为副本／取消）→ 读取目标快照预览 → 校验当前版本 → 同事务以目标全文、标题、tags、props、格式生成新版本 → 更新当前资源／派生索引 → 通知各宿主刷新。未保存草稿保护依然是 UI 职责，后端 CAS 无法保护尚未落库的输入。

例：`v1 → v2 → v3`，恢复 v1 后得到 `v4(parent=v3, restoredFrom=v1)`，不是把指针静默改回 v1。v1/v2/v3 不变。恢复同样内容且所有文档字段相同可返回明确 no-op；不能只比正文而忽略标题和 props。笔记在回收站时历史可只读；恢复内容前先按现有回收站语义恢复笔记，历史恢复不隐式取消删除。

### 保留与同步边界

建议 MVP 每次实际文档提交生成不可变版本（自动保存已有前端 debounce），最近 20 个未固定普通历史版本作为初始保留预算；当前版本、显式命名／固定版本、迁移前基线和历史引用固定的版本不自动清理。这个数是起始设计值，容量与大文档测试未执行。被清理版本返回明确“已清理”，不回退到最新内容。保留集合可能超过预算；先报告用量并允许用户管理，不能为了配额破坏固定引用。

精确历史引用必须先固定所指向的版本。MVP 可采用不可自动解除的持久 pin（会多保留，语义简单），后续再用 owner 关系做精确释放。打开历史列表不创建引用。不得直接照搬 mindmap 的 30 分钟跳过新快照并返回旧 ID：那会使新引用标注的版本与实际内容不一致。

本地 MVP 建议注册为 `BackupOnly`，仿照现有 mindmap_versions 的分类；这只是设计方向，必须验证全量数据库备份和恢复包含新表。笔记 ZIP 需要显式升级 manifest 并携带历史／资产，否则继续诚实声明“仅当前内容”。跨设备精确历史引用要到历史同步和客户端格式门槛完成后才承诺；本地版本在另一设备缺失时显示“版本未同步”，不能加载最新冒充旧版本。

**本地 MVP 的具体限制**：现有 `notes` 是 RowSync；在其上增加 `document_version_id` 可能随当前行传到其他设备，而 `BackupOnly` 历史不会随行同步到达。不能仅登记新表就上线共享文库。首轮闭环应在未参与行同步的隔离本地文库验证；推广到启用同步的文库之前，必须补齐版本传输、当前指针引用的版本到达顺序、远端正文／元数据写入的版本生成和旧客户端拒写。否则只能交付本地历史实验能力，不能宣布跨设备可恢复。这个限制不影响现有未 opt-in legacy 页继续原来的使用路径。

## ADR-05：实时引用与历史引用是不同契约

保留已有 `[[标题#章节|别名]]`、`note://id#heading` 和 `pdfref://id?page=N` 语义。heading 定位是兼容路径，改标题／重复标题时不具备稳定块身份。

建议新协议用独立 `noteref://`，避免现有 `note://` 解析忽略 query 后误开最新文档：

```text
实时块：noteref://note_fixture06?block=b_f06_intro
历史页：noteref://note_fixture07?version=nv_f07_v1
历史块：noteref://note_fixture07?version=nv_f07_v1&block=b_f07_claim
```

这三个 URL 是待实现样例，不是当前支持的跳转。独立协议还需要前端链接解析／点击路由、允许的内部 scheme、Rust 出链提取、历史读取、聊天引用持久化一起接线；仅添加 URL 字符串不会形成能力。

实时引用查当前文档：块不存在就报告删除。历史引用查指定不可变快照：历史标题、正文、块和资产均来自该快照，预览只读，用户可显式“打开当前版本”。失败分类至少区分页不存在、版本不存在／未同步／已清理、块不存在和资产缺失。不得自动模糊匹配另一个同标题块。

创建聊天历史引用时，从**同一已提交完整版本**取得引用文本、versionId 和块身份；草稿需先保存或明确生成一次完整草稿快照，不能拿未提交正文搭配旧 versionId。保存聊天消息与 pin 若跨数据库无法单事务，先 pin 再写消息，失败留下可清理的多余 pin，比成功消息指向可回收版本可靠。MVP 可先只提供本地历史预览，历史引用等 pin/解析闭环后开放。

## ADR-06：附件属于版本可恢复性的一部分

**选择**：正文 Markdown 记录稳定相对资产键，历史快照记录完整引用清单；显示用的绝对路径／Tauri asset URL 不能成为版本权威值。笔记图片一旦被版本引用，其实体不能被覆盖或因当前正文移除而回收。替换图片要创建新资产键。

版本附件清单区分：笔记自有 `notes_assets/...` 实体、外部资源引用（如 PDF 的 file ID + page）、远程 URL。自有实体必须保留才能承诺完整恢复；远程 URL 只保存 URL，未离线捕获不能承诺还原远端内容。PDF 引用保留来源和页码不等于备份 PDF 字节，若产品要保证历史原件，必须额外固定 VFS blob／文件版本。

物理资产允许删除的条件是：没有当前笔记、回收站笔记、保留历史版本或其他已固定引用使用它。当前 `notes_assets_scan_orphans` 不满足这一条件，升级后必须扩充引用集；单个 delete、bulk_delete、hard_delete、empty_trash 都必须走相同引用检查，再使用既有 file_deletion_queue。

历史 prune 与资产删除分两步：先事务性移除可清理历史引用，再把无引用资产交给既有删除队列。固定历史不能因“当前资源已切换”而丢图。仅正文快照可以先行内部验证，但附件保护没实现时不能宣称“完整可恢复历史 MVP”完成。

软删除保留历史和资产。永久删除笔记要明确范围：MVP 建议存在固定历史引用时阻止直接清除并返回引用信息；用户以后明确解除固定／确认永久移除后，才走当前日志化删除链。无需为本 WP 构建通用 GC 框架，但这几个已有删除入口必须遵守同一规则。

## 实施顺序与验收证据

建议顺序：完整文档 envelope／历史事务 → list/get/restore + 附件保护 → 逐页新格式解析往返 → 稳定块定位与引用固定 → 同步／备份和发布。历史 MVP 不必等待新的块 UI，也不能以块菜单的完成代替历史后端。

F01–F08 的预期见 [fixtures/README.md](fixtures/README.md)。需补的后端最小测试是：正文和纯 metadata 版本、空正文、no-op、A→B→A 不复用版本身份、CAS 冲突无半写、snapshot 失败回滚、恢复生成新版本、旧资源删除后历史仍可读、历史独占附件不被清理、分页稳定、保留预算不删 pin、migration legacy 基线。上述均**未执行**；现有 39 个 smoke 的通过范围仅在 baseline 第 6 节。
