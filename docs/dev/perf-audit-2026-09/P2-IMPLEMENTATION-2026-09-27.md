## 搜索：真实 WKWebView

在可见的真实应用 WebView 内，独立 React mount 使用生产 `createChatStore`、生产搜索 Hook 和真实 Worker。没有 adapter 或持久会话写入；不是完整 MessageList 页面导航验收。

前端 Vite 加载 `110551824`；当时原生外壳版本为 `0.9.68 (Build 15149, 3de1a6cd)`，该实验不依赖本次 Rust 修改。

| 输入 | Worker 请求/响应 | 峰值在途 | 最终匹配 | 最后追加后等待 |
|---|---:|---:|---:|---:|
| 500,000 字符单块，连续追加 20 次 | 3 / 3 | 1 | 20 | 624 ms |
| 50,000 字符单块，连续追加 20 次 | 18 / 18 | 1 | 20 | 36 ms |

挂起期间继续追加 10 次：**请求增量为 0，旧 Worker 已终止**。恢复时 query `late` 保留，发送一次完整快照并得到 10 处匹配。

500k 是极端长单块，不代表一般回答。这里验证的是过期任务不再无限排队及挂起停止工作；不能与原审计 Node Worker 的耗时直接计算提升比例，也未覆盖全页面搜索导航、所有平台后台生命周期或 release FPS。

首次 harness 混用了 Vite React 依赖版本，出现 Invalid hook call，保存的原始结果只有 15 秒 RPC timeout；对齐依赖图后通过，生产代码和结果断言未变。相关诊断来自工具记录，未伪造独立控制台日志。

## OCR：真实远程失败与原生回退

修正测试服务为 HTTP **503**，并使用新内容的四页扫描 PDF。实际结果：

| 系统 OCR 设置 | 模拟远程请求 | 原生结果 | OCR 就绪 |
|---|---:|---|---|
| 启用 | 4 次，全部 503 | 四页非空文本，分别 1,180 / 1,184 / 1,185 / 1,195 个字符 | 是 |
| 禁用 | 4 次，全部 503 | 无 OCR 页文本 | 否 |

启用与禁用用例均完成处理。启用时日志明确记录系统 OCR 兜底及成功，结果来自实际 macOS Vision，不是 mock 成功内容。禁用时只保留图片模式。

**初次验收脚本失败保留：**最初返回 HTTP 400，而现有代码对 4xx 在进入本地回退前直接结束，不能用它验证 R3-04；该用例还触发了既有熔断器，紧接的启用用例被拒绝。核实代码与日志后改用 503，在原冷却期结束后用单页成功回退恢复熔断状态，再执行启用四页、禁用四页。恢复单页加两个四页用例共 **9 次**模拟请求。未修改生产熔断逻辑、未放宽四页断言。

## 上传、解析、下载：真实 native IPC

OCR 和自动索引关闭，按顺序上传独立输入；期间每次查询完成后约 100 ms 发起下一次 `vfs_get_pdf_processing_status`，查询隔离库中已有文件，确实经过数据库。不是只调用 `get_app_version`。

| 输入/入口 | 大小与规模 | 命令返回 | 业务读样本 | 中位数 / P95 / 最大 | 内容核验 |
|---|---|---:|---:|---:|---|
| `vfs_upload_attachment` | 473,894 B，8 页 PDF | 2,714 ms | 28 | 1 / 2 / 2 ms | 预览页 0～7 完整 |
| `vfs_upload_file` | 1,194,104 B，20 页 PDF | 9,297 ms | 92 | 约 1 / 2 / 3 ms | 预览页 0～19 完整 |
| `vfs_upload_file` | 291,328 B DOCX，正文 XML 2,125,069 B，12,000 段 | 853 ms | 8 | 2.5 / 184 / 184 ms | 提取 1,740,889 字符，段号 0～11999 按序全部存在 |

全部业务读样本成功。P95 使用 nearest-rank；Office 只有 8 个样本，P95 等于最大值，不宜作稳定分位数解读。WebView 测得的往返包含 JS 调度、传输及后端处理，**184 ms 不能仅归因于后端，也没有前后对照证明它改善或退化**。

两份扫描 PDF 最终是 `completed_with_issues`，唯一问题为测试刻意关闭 OCR 后没有可检索文本；页预览全部保存。此处没有并行混合附件和普通上传，不能用本结果关闭 R3-01。

**Office 初次失败保留：**初始 DOCX 缺少固定 `docx-rs 0.4.19` 无条件读取的 `word/_rels/document.xml.rels`，日志为 `Failed to read from zip.`，文件保存成功但正文未提取。原失败文件和记录保留；另存仅增加空关系集合的 DOCX，保持同样 12,000 段落，单独复验通过，并以只读数据库核对全部段号。未改生产解析器，初次 91 ms 不计作成功解析性能。原综合脚本因此保留 `pass=false`，没有覆盖成成功记录。

另外单独通过 `vfs_download_paper` 下载公开 W3C `dummy.pdf`：返回耗时 1,882 ms，保存 **13,264 B / 1 页**，预览页 0 存在，提取文本 14 字符。最终只读状态为 `completed_with_issues`，`text/image` 已就绪，`ocr_processing` 记录自动 OCR 关闭的提示；本项通过的是下载、保存和预览断言，不是无告警的完整索引验收。该实验验证下载后的新本地处理路径，不包含外部 embedding。

这些输入未达到 200 MiB 上限，未测取消响应、备份维护屏障或生产常规混合负载下的延迟；没有将顺序上传结果外推为所有锁竞争已消失。
