# X4-wiring-audit：插件孤岛与服务接线审计

目标：迁移是按 lane 并行做的，存在"服务提供了但生产路径没人用"、"生产代码等某服务但一直用测试桥/替身"、"跨插件按旧名注入"等接线断点。找出全部断点并给出可执行的接线清单。

## 交付（只写 `scripts/electron-migration/wiring-audit/` 与 `docs/dev/electron-migration/audits/X4-wiring-audit.md`）
1. 审计脚本（+ 测试）：运行时加载全部插件入口取 meta（provides/inject/commands），再静态扫描生产代码中的 `ctx.<service>`、`ctx.get('<name>')`、`inject` 声明，得到服务依赖图。报告：
   - 提供了但没有任何生产消费者的服务（区分"本就是给前端/命令用的"与"真正的孤岛"）；
   - 注入/获取了但没有任何插件提供的服务名（含旧名，如 `xxx@1`）；
   - 循环依赖（inject 层面会死锁的环）；
   - 生产代码里"服务缺失时降级/抛待接线错误"的位置（`not available`、`待接线` 等），以及测试里的桥接插件/替身（tests/ 下 provide 了生产服务名的）。
2. 对照 Rust 原调用关系（`src-tauri/` 中谁调用谁，只读），为每个断点给出：应由哪条 lane 接、接在哪个调用点（Rust 文件:行 → TS 目标文件）、需要对方发布的接口。
3. 提供 `--check` 模式（有循环依赖或注入不存在的服务名时退出 1），以后接入集成门禁。
4. 不改插件代码：清单交协调者分发。

完成后贴出：服务总数、孤岛数、悬空注入数、环、按 lane 的接线任务清单。
