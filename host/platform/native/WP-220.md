| 新 lockfile / flock / OFD 文件锁 | Linux 可建立 advisory lock | 旧 WebKit 不参与新协议。`flock(2)` 原件明确不强制 IO；锁目录文件也不会覆盖子路径。旧 DB 的 SQLite 事务锁不是应用退出回执；新侧猜其锁字节不满足 D-054。 |
| SQLite 读事务、backup 或独占事务 | 引擎可协调特定数据库的读写 | 读事务允许 WAL writer；即便取得写锁，也不是旧应用/存储子进程退出。打开原库改变了已批准的“源不在原处打开”路径，不能代替离线交接；不在本包改为在线迁移。 |

## 4. 真实父退出 / 存储子进程仍活的源码边界

固定原件根：<https://github.com/WebKit/WebKit/tree/fd02d1fc7c7bb3834e9e081a5315b65a60979f62>。

1. **实际子进程身份不等于 launcher PID**：
   [ProcessLauncherGLib.cpp:247–267](https://github.com/WebKit/WebKit/blob/fd02d1fc7c7bb3834e9e081a5315b65a60979f62/Source/WebKit/UIProcess/Launcher/glib/ProcessLauncherGLib.cpp#L247-L267) 从专用 socket 取真正辅助进程 PID，源码明确要区别 bwrap/flatpak-spawn 中间进程；该内部关系没有经旧 Tauri D-Bus 发布。
2. **父连接关闭后仍有真实存储工作**：
   [NetworkProcess.cpp:239–265](https://github.com/WebKit/WebKit/blob/fd02d1fc7c7bb3834e9e081a5315b65a60979f62/Source/WebKit/NetworkProcess/NetworkProcess.cpp#L239-L265) 的 `didClose` 调用 `platformFlushCookies` 和 `session.storageManager().syncLocalStorage`，聚合完成后才检查 `stopRunLoop`；仍有 closing storage managers 时还不能停。
3. **不是同步空回调**：
   [NetworkStorageManager.cpp:1362–1375](https://github.com/WebKit/WebKit/blob/fd02d1fc7c7bb3834e9e081a5315b65a60979f62/Source/WebKit/NetworkProcess/storage/NetworkStorageManager.cpp#L1362-L1375) dispatch 到 storage workQueue，逐个 localStorageManager 同步，再 dispatch 回主 loop。
   [LocalStorageManager.cpp:153–157](https://github.com/WebKit/WebKit/blob/fd02d1fc7c7bb3834e9e081a5315b65a60979f62/Source/WebKit/NetworkProcess/storage/LocalStorageManager.cpp#L153-L157) 实际调用 `SQLiteStorageArea::commitTransactionIfNecessary()`。
4. **存在尚未提交的真实事务**：
   [SQLiteStorageArea.cpp:45,224–238,377–419,511–515](https://github.com/WebKit/WebKit/blob/fd02d1fc7c7bb3834e9e081a5315b65a60979f62/Source/WebKit/NetworkProcess/storage/SQLiteStorageArea.cpp#L224-L238) 设置 500ms 事务提交调度；setItem 开始事务并 step，提交是另一阶段。`close():87–97` 也先提交再释放数据库。500ms 是调度常量，不是可用于复制放行的等待时限。
5. **退出 watchdog 不能改成 sleep 成功条件**：
   [NetworkProcess.cpp:137–150,367–377](https://github.com/WebKit/WebKit/blob/fd02d1fc7c7bb3834e9e081a5315b65a60979f62/Source/WebKit/NetworkProcess/NetworkProcess.cpp#L137-L150) 在 IPC 关闭后安排 10s 强制退出兜底；强退不是提交成功回执，也没有证明任意旧发行版本/受阻调度都可用固定 sleep 验收。
6. **旧 Tauri 没有等待上述链的外部回执**：`src-tauri/src/lib.rs:3247–3268` 的 ExitRequested 处理插件、日志及业务后台任务；`tauri-2.11.5/src/app.rs:1106–1120` 的 cleanup_before_exit 清资源表；`1430–1436` 发 Exit 事件及 cleanup；single-instance 的 Exit handler 只 release_name。没有 NetworkProcess 退出确认或 R 级交接对象。

因此，正常关闭旧 UI 会触发存储收尾，而 UI 退出/连接断开到存储队列完成之间存在实际代码路径。**本包证明的是该边界有源码依据，未测量窗口长度、未宣称本机重现父已退出子仍活。** 一个只等待父进程/名字释放的迁移许可存在缺口，即使取样时总能见到进程很快结束也不能修补它。

已有 WP-045 `probe-webkitgtk.sh:16–17` 是等待其受控前台夹具再启动下一次读取；没有上述生产交接协议。原格式/16检查证据继续有效，其资格仍限原范围。

## 5. 最小下一步与 owner（均为请求，尚未实现/批准）

**给 C1 的裁定请求：把离线交接列为旧端/过渡发行前置，停止在此能力缺失时重复派 F2 安装生产复制。** `board/DECISIONS.md:185` 的 **U-002** 已保留“发布渠道、更新服务器、Tauri→Electron 过渡版本策略”给用户；C1 可拆实现包，不能自行认定用户已接受必须先升级某过渡版本。

最小所需不是给新端再加一个锁，而是以下旧端承诺同时成立：

1. **启动入口参与**：旧端在创建 WebContext/允许恢复重开前参与同一个源根 R 的交接协议，复制期间拒绝或等待打开该源。绑定真实 source root 与上述 recovery 候选，保持原路径/标识；锁放置位置须由 owner 与既有恢复规则协调，不能随手在 R 根加文件被 F3 当旧条目移动。
2. **可确认的收尾**：过渡旧端停止产生新的 WebView 写入，并从真实 WebKit 生命周期取得 flush/close 完成及实际存储进程退出证据。只在父进程上持有 flock、在父 exit 自动释放仍有第4节缺口；需要控制真实子进程生命周期的桥/受控监督者或经验证的引擎接缝。若选择平台托管资源，C1 先明确部署与支持范围，不能默认普通旧版本已被托管。
3. **交接持续至复制结束**：新端获得的是仍被维持的交接权，不是可过期的布尔“已退出”文件。旧端/监督者异常或连接失去时不得据此把未知状态升级为成功；没有 writer 退出证据则重试/退出。结束复制后才按协议释放；不默认扩大到永久阻止用户回退。
4. **未协作旧版本的受支持流程**：由 U-002 确定如何把正常用户带入参与协议的发行入口；旧版本没有协议时不能降为“让用户点我已关闭”就给生产成功。也不把问题扩大为阻止用户故意运行任意历史二进制的通用隔离系统。
